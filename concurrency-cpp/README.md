# Домашка: примитивы синхронизации своими руками

Стандартная библиотека прячет всю сложность за `std::mutex` и `std::latch`.
Здесь мы её достаём: каждый примитив пишется с нуля поверх атомарных операций
и двух системных примитивов «усни на адресе» / «разбуди спящих на адресе».

Никаких `std::mutex`, `std::condition_variable`, `std::shared_mutex`,
`std::call_once`, `std::counting_semaphore`, `std::latch`, `std::barrier`
и `std::atomic::wait` внутри решений — только `std::atomic` и `internal/futex`.
В тестах и в своих проверках пользоваться стандартной библиотекой можно.

## Задания

| папка | что писать |
|---|---|
| `01_spinlock` | спинлок и его версия с предварительным чтением (TTAS) |
| `02_mutex` | мьютекс с быстрым путём и засыпанием через futex |
| `03_semaphore` | счётный семафор |
| `04_waitgroup` | счётчик незавершённой работы |
| `05_once` | выполнить функцию ровно один раз |
| `06_rwmutex` | много читателей или один писатель |
| `07_barrier` | точка сбора на N участников, переиспользуемая |

Идти лучше по порядку: каждый следующий примитив опирается на понимание
предыдущего. В каждой папке лежит README с разбором того, как эта штука
устроена и что в ней ломается, если сделать наивно.

Писать нужно в `*.cpp` рядом с заголовком: объявления уже на месте, тела
методов пока бросают `не реализовано`.

## Как запускать

Всё гоняется через `make`. Написали примитив — проверяете его одной командой:
она соберёт всё с включёнными предупреждениями, прогонит тесты, тесты под
детектором гонок и двадцать повторов подряд.

```
make mutex
```

Так же для остальных: `make spinlock`, `make semaphore`, `make waitgroup`,
`make once`, `make rwmutex`, `make barrier`. Можно и по имени папки —
`make 02_mutex`, кому как удобнее.

Когда написаны все:

```
make test      тесты всех примитивов
make race      то же самое с детектором гонок
make stress    по сто повторов каждого теста
make bench     бенчмарки
make check     сборка + гонки + стресс одной командой
```

Под `make` лежат обычные бинарники в `bin/`, так что точечно можно и руками:

```
./bin/02_mutex -run=TestMutualExclusion -v
./bin/02_mutex.race -count=100
```

Флаги у бинарника: `-run=РЕГЭКСП`, `-bench=РЕГЭКСП`, `-count=N`,
`-timeout=2m` (сколько отпущено одному тесту), `-v`.

Тесты написаны с таймаутами: неверная реализация не повесит прогон, а упадёт
с внятным сообщением.

Нужен компилятор с C++20 (clang или gcc) и `make`. Детектор гонок — это
ThreadSanitizer, он идёт в комплекте с обоими компиляторами.

## Про futex

`internal/futex` уже написан, трогать его не нужно.

`Wait(addr, val)` засыпает, если по адресу всё ещё лежит `val`. Проверка и
засыпание атомарны — иначе между ними успело бы вклиниться пробуждение,
и поток заснул бы навсегда. `Wake` будит одного, `WakeAll` — всех.

На Linux это системный вызов `futex(2)`. На macOS и Windows его нет, поэтому
там лежит эмуляция поверх `std::mutex` и `std::condition_variable` — она нужна
только чтобы задания собирались везде.

`internal/testing` — мини-аналог гошного пакета `testing`, тоже трогать не нужно.

Готово, когда `make check` зелёный.
